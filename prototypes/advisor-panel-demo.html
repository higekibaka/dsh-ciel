先立「疑点生命周期」，再谈探索工具
思路探索型批评者的风险不在工具而在报告纪律。参考 Gerrit 的 Verified ±1 心智：每条批注标注「已核实 / 未核实」，让证据状态成为一等公民，探索只是改变这个字段的来源。
陷阱直接给工具会让误报率看起来「变低」（探索总能找到点相干证据自圆其说）——没有「排除数」对外可见时，模型会偏向全部确认。
验证目标同一批种子草稿，「确认」批注中引用到真实文件/命令输出的比例 ≥ 90%
high
块切分算法是整个 0.12.0 的单点故障
思路host 与 client 各写一份切分迟早漂移。把切分器做成纯函数放进共享夹具：同一组 markdown 样本，两端输出块号必须逐字节一致——这是比 UI 更先该写的测试。
陷阱嵌套围栏代码块（```` 包 ```）、列表里的懒人换行、表格跨行，这三类样本最容易让两端序号错位。
验证目标≥12 组边界样本双端块号零错位；错位样本在 CI 中红过至少一次（证明夹具有牙）
mid
分诊默认值比交互形式重要
思路「默认全部采纳」与「默认只采纳 blocker」是两种产品。前者信批评者、人纠误报；后者信人、批评者只做风险提示。按 nit 的历史误报率选，别按直觉选。
陷阱默认全采纳 + 一键回传的组合，会把分诊率训练成零——用户发现不点也够用，就永远不点，误报照样进上下文。
验证目标回传装配的批注子集与 UI 勾选状态逐条一致（含重启水合后）
low
裁决卡的左色条别用 severity 混色
思路pass 用绿、changes 用琥珀，一条色条就是结论本身；混色渐变会让「建议修改」在余光里读不出来。
陷阱——（低危条目可以没有陷阱，这正是 low 档的含义）
验证目标缩略图尺度（25% 缩放）下，pass / changes 两态可一眼区分
