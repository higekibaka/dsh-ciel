# Ciel 0.17.0（历史）：评审只限时

> **本文是 0.17.0 的历史交接，描述当时「只限时、仍用原生读工具」的状态。**
> 0.18.0 已把工具化核实阶段改为受限 PTC（`run_code` + 私有 QuickJS/WASM），
> 见 [受限 PTC 评审交接](ptc-review.md)。下面关于「本次没有切换 PTC」的表述
> 只对 0.17.0 成立，不要当作当前行为。

## 已完成

评审不再因查询次数或模型请求次数用完而停止。默认总时限仍为180秒，可在「设置 → 夏尔 Ciel → 常用设置 → 评审最多等多久（秒）」修改（10–600秒）。准备资料、存疑、核实共用一个截止时间，切换阶段不重新计时。

- 查询次数和模型请求次数继续统计；它们不再是执行配额，也不再用于截取疑点。宿主将结构化清单中的全部疑点（当前格式至多8项）按重要性排序后交给核实阶段。
- 工具结果携带 `review_time`，进度显示剩余秒数和已查询次数。旧评审记录的次数分母、抢救标记仍作为历史数据显示。
- 时间到或用户停止时中断工作并清理子代理；不额外启动模型整理、不自动延长时限或重试。正常完成和无法继续的错误也可提前结束，不是必须跑满时限。
- 保留文件权限、敏感内容检查、不可变源码副本、内存/证据/记录大小保护及单条模型输出长度限制。只限时不保证查看所有文件，也不是费用上限。
- 顾问的工具策略、调用额度和时限未变。**0.17.0 没有切换 PTC**（历史事实；0.18.0 才切换到受限 PTC，见 [ptc-review.md](ptc-review.md)）。

## 旧设置

`criticExploreBudget` 和 `criticMaxRequests` 可继续存在于旧配置中，但已隐藏、无默认值，不参与任何新评审执行决策；不需要手动清理它们。包括旧 `criticExploreBudget: 0` 也不再关闭文件核查。要禁止查文件，请关闭「允许评审时查文件」（`criticExploreEnabled`）；这仍会调用模型分析草稿。总开关 `enabled` 的行为不变。

## 验证

- 单元测试：390/390。覆盖旧次数值0/1/20/50被忽略、超过旧模型请求上限、全部疑点送入核实、资料准备超时、两个阶段共用时限、过期后不执行工具，以及停止/卸载清理。
- 实际 DSH 0.1.5-alpha.2 的离线执行链：22/22。使用脚本模型，不调用外部模型；75次批量读取与70次连续查询/72次模型请求均可越过旧上限完成；真实10秒超时取消成功且没有额外模型。
- Chromium 夹具：22/22，页面错误和 console 错误均为0；使用实际原生资源/侧栏服务与完整生成客户端，业务记录是合成数据。
- 实际 SettingsRoot 的离线回归通过：次数控件消失、总时限说明存在，旧字段保留但不修改，草稿保存和原生控件行为正常。
- 该版本只做隔离验证；未修改真实设置或凭据，也未清理用户记录。

## 生效与材料

宿主插件已修改，**需要重启 DSH，再刷新页面**。仅刷新不足以更新已加载的后台逻辑。不自动重启正式实例，也不新开替代服务器。

- `plugin/index.js`：只限时编排、权限守卫、计数与进度。
- `plugin/review-runner.js`：工具返回剩余时间和查询统计。
- `plugin/client.js`：已从 `plugin/src/` 重建的客户端。
- 复现：`node --test plugin/test/*.test.js`；`DSH_CHECKOUT=/path/to/deepseek-harness node scripts/verify-runtime.mjs`；`DSH_CHECKOUT=/path/to/deepseek-harness TSX_TSCONFIG_PATH=$DSH_CHECKOUT/tsconfig.base.client.json node --import tsx/esm scripts/verify-sidebar-native.mjs`。
