# Ciel 0.18.0：受限 PTC 评审

> **状态：实现与验证已完成。** 宿主变更需**重启 DSH 并刷新页面**后生效（建议手动重启）；
> 正式实例上的人工 GUI 验收仍待进行。

## 一句话

0.18.0 把评审的**工具化核实阶段**从"直接调用原生 read/grep/glob"改为
**只给批评者一个原生保留的 `run_code` 通道**：批评者程序在 Ciel 私有的
worker + QuickJS/WASM 里运行，只能通过
`JSON.parse(await tools.read/grep/glob(...))` 查询**评审开始时的内存源码副本**。

## 你会看到什么变化

- 核实阶段的模型**只能调用 `run_code`**；直接调用 read/grep/glob 会失败。
- 程序内可用的工具只有 `read` / `grep` / `glob`：
  - `grep` 是**字面量搜索，不是正则**；`glob` 支持 `*`、`?`、`**`。
  - 每个嵌套调用返回 **JSON 字符串**，必须 `JSON.parse`。
  - 返回值带宿主发放的 `evidence_refs`（`e1`、`e2`…）和 `review_time`
    （`remaining_ms` / `tool_calls` / `model_requests`）。
- 程序本体只接受 **TypeScript 可擦除语法**（类型注解等）；`enum` / `namespace`
  等不可擦除语法**明确失败**，不会静默降级。
- 两阶段不变：**存疑/纯草稿阶段仍然无工具**，只有核实阶段使用 PTC。

## 安全边界

- 批评者程序运行在 **Ciel 私有的 worker + QuickJS/WASM**，不是 DSH 库存
  worker 代码运行时。库存运行时在宿主机上**可以读取整机文件并启动进程**，
  会绕过评审的源码副本。
- 宿主用**私有官方 `ToolRuntime` + 私有 `codeRuntime` + 惰性私有 prompt sink**：
  - `review-runner.js` 是受限子代理的主入口：在子会话 setup 中呈现 PTC、
    限制继承工具、注册只读快照接口。
  - `index.js` 持有控制守卫与两阶段编排/提示词；作用域 `tools/execute`
    钩子**只把该评审子会话的外层 `run_code`** 路由到私有的官方 PTC 定义。
  - 私有注册表沿用 DSH 嵌套调度与日志格式，由 Ciel 守卫控制范围与时限。
  - 隔离的私有注册表不会把嵌套 `tools/result` 事件送入根观察者，因此并非所有全局策略插件都作用于评审子会话。
- **根 `codeRuntime` 不变**，不做全局运行时替换，不共享完整 preset。
  语言不匹配或能力缺失时，工具化阶段**直接失败**，没有不受限回退。
- 源码来自**评审开始时筛过的不可变内存快照**：没有实时文件、文件系统、bash、
  网络或 session 工具；排除凭据、私钥、DSH 会话状态、符号链接、硬链接和非普通文件。
- 取消或到点会**硬终止 worker 并排空嵌套调度**；不追加抢救写入、不自动延时或重试。

## 证据如何进入模型

- 程序收到的是**宿主裁剪后的精确回执**（每条默认 16 KiB / 200 行；每轮合计
  128 KiB / 128 条）。
- 只有**程序打印/返回的摘要 + 必要的原始片段/路径/行号/evidence_refs**
  会进入**模型上下文**。程序可以读取很多内容，模型只看到它主动带出的那部分；
  未带出的内容对模型等于不可见。
- `e1`、`e2` 等编号由**宿主发放**，模型只负责在结果中引用它们。宿主只校验
  编号确实存在于本次账本；这**不证明模型的引用或推理为真**，也不证明被引用内容
  与草稿判断一致。
- 原生子会话日志可能保留**每一次嵌套查询**（超出 Ciel 归档范围）；Ciel 的
  片段/记录限额只约束自己的记录，不是全局无痕承诺。

## 时间与额度

- 共用**一个总时限**：默认 180 秒，可配 10–600 秒，覆盖**资料准备 + 存疑 + 核实**。
- **每个 PTC 程序拿到的是剩余时间**，不重新计时；切换阶段也不重置。
- 查询次数和模型请求次数**只统计，不再触发中止**，也不据此截取疑点。
- 内存、输出、语料、证据、存储上限仍是**安全/协议边界**，不是查询配额。

## 依赖与兼容

- 新增可选 peer 依赖 `@deepseek-ai/dsh-tools >= 0.1.5-alpha.2`（受限 PTC 用；
  缺失时评审失败，不退回普通文件工具）。
- 插件依赖固定 `quickjs-emscripten 0.32.0`。
- 未修改 DSH 源码、未替换全局运行时、未改动用户的设置/凭据/会话。
- 客户端插件改动不会自动热更新（除非另行运行 `pnpm run dev:web`，且只覆盖客户端 bundle）；本版不承诺 HMR。

## 验证结果

- 默认 PTC 执行链 **37/37 通过**（0 失败、0 网络；执行链测试使用脚本模型，未做额外的真实模型评审/A/B 测试）：单程序
  75 次嵌套读取（3 次模型请求）、70 程序 / 72 请求、curation 与 `eN` 引用、
  私有拒绝、类型错误、3 个取消场景、真实 10 秒总时限；缺失/错误运行时在
  核实阶段前失败（存疑阶段仍允许 1 次模型请求），根运行时不变。
- 单元测试 **428/428**（含运行时 15 项）。
- Chromium 夹具 **22/22**（页面/控制台错误 0、网络 0）；原生 SettingsRoot
  回归通过（网络/模型 0）；生成客户端 `--check` 与源码一致。
- 候选包冒烟 **18/18**：解包 **12 个文件**、仅安装 production 依赖、从 `/tmp` 运行真实 QuickJS（Promise 批量 / `.then` / `for-await`）与模块相对 worker 定位均通过。缓存缺失时 `--prefer-offline` 会拉取依赖包，因此**打包/安装过程不保证全程 0 网络**；执行链测试本身为 0 网络。
- 环境限制：只在 **Node 24.20.0** 验证；兼容下限 **Node 22.19 尚未测试**。
- 以上为**合成业务数据与原生 UI 组件**，不等同正式实例部署/验收。测试网络 0
  只说明测试本身，不代表整个开发任务没有真实模型调用。
