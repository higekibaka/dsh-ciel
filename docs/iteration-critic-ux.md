# 批评者体验迭代计划（0.12.0 → 0.13.0）

> 状态：已立项（2026-09-01，会话内与作者对齐）。本文档是实施层计划；
> 哲学论证见 [design.md](design.md)，本计划的每一项都标注了对设计原则的
> 影响审计。体验原型：`prototypes/verdict-card-demo.html`（0.12.0 裁决卡）、
> `prototypes/exploratory-critic-demo.html`（0.13.0 探索型批评者：进展流 +
> 排查/证伪/排除统计 + 已核实/条件风险证据标签）。

## 背景诊断（为什么现在「怪」）

1. **范式错配**：评审呈现借用了拼写检查范式（侵入式红波浪线），只见零散
   下划线、不见「这份草稿行不行」的全局结论。
2. **锚定脆弱**：纯文本就近匹配（last-occurrence proximity），流式更新、
   重复引文、消息编辑后错位——bug 级问题。
3. **生命周期割裂**：点击后 5–10s 无状态反馈，结果以 DOM 突变砸到原文上。
4. **信噪比失控**：一键回传把误报 nit 一并注入主模型上下文。
5. **证据天花板**：批评者无工具，疑点只能以「条件风险」措辞踢回给人类，
   单条批注价值密度低（0.13.0 解决）。

## 原则审计基线

不可动：批评者**只裁决不代写**（无修复建议、无对话追问）；不读作者心路
（思维链/工具叙事）；交付物是证伪。以下各项均在红线内。

---

## P1（0.12.0）：裁决卡范式 + 块级锚定 + 分诊 + 生命周期

### ① 评审输出契约 v2（host，向后兼容）

批评者回复新增 verdict 头，批注锚点从「纯引文」升级为「块号 + 可选引文」：

```text
## verdict: pass | changes
summary: 一句话总评

### [blocker] title
block: b3
anchor: a verbatim quote from block b3（可选，用于块内高亮）
comment: …
```

- `pass`：无 blocker（nit 可以有）；`changes`：至少一条 blocker。
- 无 verdict 头的回复按旧契约渲染（旧 sidecar 记录、模型未遵守时的兜底），
  兼容性由解析层吸收，不做数据迁移。
- host 在送审前对草稿做**块切分**（见 ②），把块地图（`b1: heading, b2:
  code, …`）与**原始草稿**一并提供给批评者；anchor 引文仍必须是草稿原文
  的逐字符子串（不含任何注入标记）。

### ② 块级锚定（host + client 同一算法）

- 切分规则刻意简单：**markdown 顶层块**——按空行 / 标题 / 围栏代码块 /
  列表 / 表格边界切分，序号即块号（b1…bN）。host（index.js）与 client
  （client.js）各实现一份，共享单测夹具保证一致。
- client 渲染：消息正文顶层 DOM 容器即块（与切分序号对齐），左侧 gutter
  徽章（▲ blocker / ● nit），点击弹出批注卡并高亮该块；**不再向文本节点
  插入任何 span**（旧划线模式仅用于渲染无 verdict 头的旧记录）。
- 接受风险：host 切分与渲染 DOM 序号错位 → 单测覆盖常见块型；错位块
  降级为块级定位失败时退回旧 proximity 行为。

### ③ 生命周期状态徽标（client）

消息操作区状态机：`idle → reviewing（spinner + "评审中（critic 子代理）…"）
→ done（⚠ N 条批注（X blocker · Y nit），可点击展开）/ failed`。
评审期间不触碰正文 DOM；完成后裁决卡滑入、gutter 淡入。
数据来自现有 review store（按 reviewId 归键的状态），无新增 host 通道。

### ④ 分诊与选择性回传（client + 既有 feedback WAL）

- 每条批注 采纳/忽略（默认采纳），「全部 / 只看 blocker」过滤；
- 「回传」按钮实时显示采纳数，仅装配采纳子集；保留「仅回传 blocker」
  快捷通道（= blocker 采纳 + 其余忽略）；
- 分诊状态持久化：复用 feedback WAL 的 per-review 结构（扩字段，不新增
  存储）；旧 WAL 记录缺省视为全部采纳。

### ⑤ 发现性轻提示（捎带）

消息操作区徽标同时承担「已评审/未评审」指示；已评审消息重新水合后徽标
直接显示 done 态（数据本就在 sidecar）。

### 0.12.0 验收清单

- [ ] parseCriticVerdict 单测：v2 全字段 / 无 verdict 头 / verdict 非法值
- [ ] 块切分双端一致性夹具（≥8 种块型组合）
- [ ] 旧 sidecar 记录渲染回归（proximity 路径保留）
- [ ] 分诊状态重启后水合
- [ ] 回传装配仅含采纳子集（含全忽略时禁用按钮）
- [ ] 原型 demo 的交互在真实消息流复现（advisor-test 实例实拍）

## P2（0.13.0）：探索型批评者（证据天花板拆除）

### 契约 v3：存疑 → 核实 → 断言

```text
阶段 1（本地，无工具）：草稿 + 请求 + 裁决摘要 → 疑点清单（每条附证伪方法）
阶段 2（定点探索，只读工具，预算 ≤5 次调用）：逐条执行证伪方法
阶段 3（verdict 输出）：确认的批注必须引用探索所得证据；
        排除的疑点不得出现在批注中，只计入统计
```

裁决卡统计行扩展为：`排查 N 处疑点 · 证伪 X 处 · 排除 Y 处`。

### 护栏（红线内的探索）

- **世界可以碰，过程不许碰**：只读工具白名单（读文件/搜索/只读命令），
  禁会话历史访问，禁写操作，禁子代理套娃；
- 探索预算硬上限（默认 5，进设置 ns）；
- 延迟代价：评审时长 5–10s → 30–60s，③（生命周期徽标）是前置依赖，
  已排在 P1；
- 模型能力：多步调查超出 gemini-flash 量级舒适区，上线前用 critic 路由
  可配做 A/B（flash vs 更强模型），按「批注确认率 / 误报率 / 耗时」决定
  默认路由是否上调。

### 进展通道：轮询制落地，agent-team 推迟（2026-09-05 再修订）

**新事实**（本日实拍，见上方 ⚠ 竞态记录）：(1) `tool-agent-team` 挂载即概率性
打死所有一次性 spawn——邮箱通道的地基本身不稳；(2) `spawnTeammate` 请求
**不支持按次 pin 模型路由**（provider 字段指 spawn 提供方，LLM 路由在
team 包 profile 配置层），接入即丢失 criticProvider/criticModel/effort
三枚 pin——而 A/B 恰好在评估期需要它们。

**决策**：黑盒问题（30–60s 无反馈）由**轮询制进展通道**解决，已上线：
- host 新增 `advisorReview/progress` Remote 方法：评审在途期间返回
  `{inFlight, explore, budget, toolCalls, elapsedMs}`，计数来自预算看门狗的
  事件流采样（与熔断同源，非模型自报）；
- client 评审中每 2s 轮询，徽标 `评审中 · 排查 k/预算…` 实时递增；
- 实拍证据：标签序列 `0/5 → 1/5 → 3/5 → ✓ 无阻断`，终态自报
  `排查 3 · 排除 3` 与采样递增精确吻合。

`criticTeamEnabled`（邮箱叙事进展「疑点 i/M」+ teammate 化）**推迟**到上游
竞态修复且路由桥接有官方通道之后；设置项暂不注册，避免挂出一个必坏的
开关（验收项随之改写，原「服务缺席明示失败」诉求由轮询通道的
`{inFlight:false}` 语义天然满足——通道不存在即退回黑盒，无需配置）。

> 旧方案存档（9-04/9-05 版）：agent-team 邮箱通道 + 手动勾选
> `criticTeamEnabled`。原型实证（lead 会话 `team/message/queued` ×13 +
> `delivered` ×13 耐久落盘）仍然有效，竞态修复后可直接复活：三根接线
> （进展映射 / 路由桥接 / 纪律归 ciel）与本节护栏不变。

### 护栏（红线内的探索）

- **世界可以碰，过程不许碰**：只读工具白名单（read/grep/glob），
  禁会话历史访问，禁写操作，禁子代理套娃；
- 探索预算硬上限（默认 5，进设置 ns）：prompt 纪律为主、看门狗熔断兜底
  （实拍：budget=1 时模型自限 1/1；熔断单测覆盖）；
- 延迟代价：评审时长 5–10s → 30–60s，③（生命周期徽标）+ 轮询进展通道
  已消化；
- 模型能力：多步调查超出 gemini-flash 量级舒适区，上线前用 critic 路由
  可配做 A/B（flash vs 更强模型），按「批注确认率 / 误报率 / 工具误用率 /
  耗时」决定默认路由是否上调——实拍已记录一例 glob 模式误用造成的
  「证据为真、结论为假」误判（工具误用率的地面真值首样本）。

### 不做的（再次记录）

批评者对话追问、修复建议——背叛独立判官定位，见 design.md 角色边界；
omdsh-dev/dsh-advisor 的被动注入式评审是另一条路线，不追随。**持久顾问**
（teammate 化的 ask_advisor）同样不做：顾问的价值来自每次咨询的独立性，
持久上下文会积累共同框架、损害分布多样性——邮箱改变通信成本，不改变
这个认识论约束。

### 0.13.0 验收清单

- [x] 疑点→证伪→断言三段式契约单测（含排除项不得泄漏进批注——dossier
  段伪装 `###` 头不落批注；无证据 blocker 降级 nit）——0.13.0 第一轮
  落地：parse 层 dossier/verdict 分段、stats 行、evidence 字段、
  只读白名单（read/grep/glob）+ 预算轮询硬熔断（abort）、评审条目带
  模型自报 stats 与运行时实采 toolCalls 交叉校验
- [x] 进展通道：`advisorReview/progress` 轮询制上线（实拍标签
  `排查 0/5 → 1/5 → 3/5` 与终态自报精确吻合）；**修复两处 Remote 注册
  缺口**——客户端 `ADVISOR_REMOTE` 描述符漏 `triage`/`progress`（triage
  自 0.12.0 起从未真正到达 host，现一并补上）；agent-team 邮箱通道因
  上游竞态 + 路由 pin 缺口推迟（决策与复活条件见正文）
- [x] 只读工具白名单与预算硬上限的**真实例**执行证据（advisor-test 实拍，
  2026-09-05）——白名单生效（三轮实拍仅用 read/glob，零写工具）；预算
  传导到 prompt 且被遵守（budget=1 时实测 1/1）；硬熔断看门狗
  （createBudgetWatchdog）单测覆盖「不超不熔断 / 超限一次性熔断 / 子代理
  缺席容错」，真实例未触发（gemini-3.7-flash 遵从预算纪律，五文件多
  疑点场景也自我压缩到 1 次调用）
- [ ] 条件风险措辞在可证伪场景下绝迹（升级为证据引用）——部分实证：
  证伪路径两条 blocker 均带行号级 evidence；**发现新风险**：批评者工具
  使用能力本身是质量维度（实拍中 `glob "./*.js"` 模式误用 → "No files
  found" → 把正确答案误判为 blocker，证据为真、结论为假——evidence
  引用设计恰好让此类误判可被人一眼识破），A/B 需纳入「工具误用率」
- [x] 客户端渲染：裁决卡统计行（排查 N · 证伪 X · 排除 Y + 实测调用数）、
  批注 evidence 展示、降级标记——0.13.0 第二轮落地（dsr-vchip-s /
  dsr-evidence / dsr-downgraded）
- [ ] A/B 报告：确认率/误报率/耗时，默认路由决策记录
