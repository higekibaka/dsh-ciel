# 历史宿主事实与逐项证据

<!-- ciel-doc: current -->

以下功能已纳入 Ciel 0.20.0。

## 解决什么问题

逐项独立调查并不自动带来足够证据。原来的调查者只有静态源码副本和较短的作者工具摘录，无法从源码推断某条旧回复实际使用的模型、当时权限或工具声明；目录输出还可能在 1600 字符处被 Ciel 再次截短。

本版补足证据来源，不改变“有证据才排除或确认问题”的规则，也不保证一份回复的全部断言都正确。

## 最小披露范围

| 证据类型 | 来源和时间 | 可以说明 | 不可以推断 |
|---|---|---|---|
| `host-fact / session-metadata` | 目标回复及其之前的日志；仅投影白名单字段 | 回复记录的 provider/model、请求路由、最后记录的文件策略/审批枚举、请求头中的工具名称 | 物理模型权重、当前设置、审批一定获准、密钥已配置、网络/工具一定执行成功 |
| `tool-output / session-tool` | 目标之前同一回合的允许工具结果 | 作者当时实际收到的输出文本及错误标志 | 独立重跑、输出内容绝对真实、未来状态不变 |
| `directory / snapshot-metadata` | 评审启动时、已批准根目录的浅层条目 | 可见文件/目录/链接名称及类型 | 旧回复当时状态、符号链接目标内容、过滤后缺项必然不存在 |
| 原有 `source / review-tool` | 不可变源码副本中的实际读取 | 保存片段的原文、行号和哈希 | 未读取部分或整个仓库均正确 |

不传递原始请求头、工具 schema/描述、系统提示词、凭据、完整配置或完整会话。模型、策略和工具字段缺失时保持未知，不拿今天的默认设置填补历史。PTC 请求头若只声明 `run_code`，不据此断言某个嵌套工具不存在。

## 存储与截断

- 作者输出只取允许的本轮 `bash`、`web_search`、`web_fetch` 及 `review-evidence-policy.js` 白名单中的 Playwright 工具文字结果；不传截图像素、不执行浏览器。私有路径和敏感检查不变。不保存调用参数。
- 单条摘录可使用现有 8000 字符总预算，不再额外卡在 1600 字符。总预算和引用归档的 16 KiB / 200 行、128 KiB / 128 条保护不变。上游明确截断的输出不会被伪装成完整。
- 自动提供的元数据与历史工具摘录合计最多使用一半引用归档字节额度，保留另一半给调查者读取决定性源码；超限片段明确标记，不静默占满后续取证空间。
- 原文、来源、历史观察时间与本次归档时间分别保存。旧 `reported/author-tool` 空标记不迁移，不虚构原文。
- 根目录元数据先于递归源码捕获，拥有有界枚举；源码 8 MiB/文件数用尽不会隐藏后面的顶层目录名。敏感/受保护/排除的名字仍不披露；不跟随链接，也不因此开放其内容读取。
- 目录变化、枚举不全和证据片段不足明确标记。目录清单是过滤后的观察，不能用缺项直接证明物理不存在。

## 覆盖与 Jev

完整覆盖只针对本次提名疑点及其实际引用的证据。实际未核实项、引用片段截断和缺少用户请求仍会降级。无关源码没有全部捕获，不应使一个已经有完整历史模型记录的模型身份判断永久变成部分覆盖；全局范围限制仍保留在界面。

Jev 开关默认仍为关闭。开启后，新类型的最终引用原文也可发给配置的服务（默认 TypeSafe），并附带来源、时间和错误标志；只发送最终引用证据，不发送全部可用事实。真实历史工具输出可以检查，旧的空来源标记不能检查。缺少精确主张、敏感内容、截断和 24 KiB 状态上限照常跳过。

这些记录及哈希证明的是宿主保存了什么，不提供防篡改、推理正确性或绝对保密保证；敏感检查是启发式的。核查结果仍需人工结合原文审阅。

## 验证与生效

新增回归涵盖历史时间绑定、未来设置不能覆盖过去、白名单排除密钥/schema/replay、PTC 声明范围、短目录输出完整保留、截断传播、浅层目录独立于源码预算、引用归属、Jev 新证据投影及页面来源提示。

无网络脚本模型场景使用真实 DSH 注册表、代理循环、受限 PTC 与保存/读取接口。它验证执行链，不证明真实模型会作出特定裁决。对报告中旧回复的只读投影已确认：三类宿主事实可取得，完整的 2336 字符工具输出包含原先被截掉的目录名；没有重跑付费评审。

Host 模块更新需要重启 DSH，浏览器刷新后加载新界面；现存评审不自动迁移或重跑。需要新结果时重新点击批注评审。
