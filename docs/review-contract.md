# 评审结果契约 v4.1

本文描述未发布稳定性修复的当前实现。旧评审 JSONL 记录不迁移，仍按原字段读取。

## 两阶段输入

存疑阶段只看用户请求、草稿及块地图，不能使用工具，也看不到作者的工具结果或顾问建议。合法的 `## suspects` 空清单与无法解析的回答不同；空清单不表示事实已经核实。

宿主为清单逐项分配 `s1`、`s2` 等编号，按重要性稳定排序，再按工具额度选择。核实阶段只收到被选中的编号，以及宿主整理的作者工具证据和顾问清单。不允许新增编号；意外发现的新问题留到后续评审，避免绕过分诊。

## 核实结果

```text
## dossier
- result: s1 | outcome: cleared | evidence: read file.txt:1-3，实际为三行
- result: s2 | outcome: defect | evidence: read config.json:4，值为 false 而非 true
- result: s3 | outcome: unchecked | evidence: none

## verdict: changes
summary: 一句话

### [blocker] 配置值写反
suspect: s2
block: b2
evidence: read config.json:4，值为 false
anchor: 配置值为 true
comment: 草稿的配置断言与文件内容冲突。
```

三个互斥结果：`defect` 表示疑点证实为缺陷；`cleared` 表示疑点已排除；`unchecked` 表示没有了结。`defect` 与 `cleared` 必须带非空引用字段。关键词大小写和字段周围空白可规范化；重复编号、缺失结果、无引用结果不能充当已核实。

批注只接受选中编号的 `defect` 结果，并约束到该疑点的草稿块。未知、未选中、已排除、未查编号上的批注被剔除。缺陷结果若没有对应有效批注，会退回未查，不能留下“证伪一项、零批注”的矛盾记录。若批注漏掉重复引用，宿主携带该编号结果行的引用。

## 宿主记账与展示

模型自报的 stats 不再参与新评审的记账。疑点总数固定为存疑清单长度；宿主对每项最终结果计数，未送审项固定为未查。因此总数 = 证伪数 + 排除数 + 未查数。一次工具读取可能解决多个疑点，工具次数不能用作已查疑点数。

宿主也从账本生成卡片总评，不让模型自由摘要绕过未查边界，宣称未读取的文件已经全部成立。具体缺陷解释留在批注中；引用仍可人工检查。

覆盖范围与严重度分开：裁决由保留下来的 blocker 决定，未完成/抢救/契约偏差影响的是评审完整性，不是给草稿强加缺陷。模型乱加的建议会被剔除，界面提示原因。合法零疑点和关闭探索的纯草稿评审不宣称独立工具核实。

## 运行边界

- 工具可见集限于 read/grep/glob，使用 `tools.guard()` 在执行前同步计数、拒绝越限；轮询只采样进展并在终态补查。
- 各阶段使用独立中止控制器，但共享用户取消/总超时/总请求额度生命周期；插件卸载等待已拥有的子代理清理。
- 仅工具预算熔断且有选中编号的带引用部分结果时允许一次无工具抢救；网络/鉴权错误、取消、超时、请求额度耗尽不自动抢救。熔断前的有效结果冻结保存：抢救者只编写裁决，不能因为自己没有工具就抹掉先前已排除的疑点，也不能把未查项改成已核实。抢救输入不混入作者的工具活动摘要，以免把“作者没做”误认为“核实者没做”。
- `criticMaxRequests` 统计 Agent 步骤请求，提供方内部传输重试由 DSH 管理。所有这些边界都不是金额保证。

## 保证与非保证

程序保证选中范围、编号关联、计数与显示不互相矛盾；它不证明模型的证据引用或推理为真。模型仍可能给错严重度、算错比例，或错误地把某个判断归到一个有效编号上。证据必须可见，作者修复前仍需核对，不能把“结构校验通过”当成真理认证。只读白名单也不等同于敏感文件隔离；文件访问仍受 DSH 调用方沙箱控制。
