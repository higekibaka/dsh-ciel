# 评审读取隔离与模型标识

当前实现的模块边界与后续决策见 [architecture.md](architecture.md)；行为验收以 [review-contract.md](review-contract.md) 为准。以下内容保留设计依据。

## 使用者需要知道的事

- 评审不再直接调用普通文件工具，而只查询**评审开始时生成的受限源码资料副本**。默认来源是当前会话工作目录中的允许源码和文档；设置中的“额外允许查看的源码目录”可明确追加外部源码目录。
- 凭据文件、DSH 会话状态、修复备份、私钥和其他受保护资料不收录。符号链接、硬链接和非普通文件不收录。普通 `auth.ts`、`token.js` 等实现代码并不会仅因名字而被禁止，但仍接受内容检查。
- 核实阶段的模型**只能通过 `run_code` 程序**调用 `read`、`grep`、`glob`（`JSON.parse(await tools.read(...))` 这种形式），不能直接调用它们。它们都在同一份内存副本内工作，不读取或搜索实时主机目录。`grep` 是**字面文本搜索，不是正则表达式**；`glob` 支持 `*`、`?` 和 `**`。
- 核实结果由宿主在真实 `read`/`grep`/`glob` 输出上分配 `e1`、`e2`… 引用；随评审保存的只有被引用且有界的片段（每条默认 16 KiB / 200 行，每轮合计 128 KiB / 128 条）。**程序收到的是宿主裁剪后的精确回执，模型上下文只收到程序打印/返回的精选摘要和必要片段**；不要把「程序读到」当成「模型看到全部文件」。`a1` 只标记作者提供的输出，原文不另存。
- 新记录写入 `$DSH_HOME/ciel/v1/<kind>/<sessionId>/<hash(id)>.json` 的版本化原子记录（`reviews`/`evidence`/`advice`，保留 `calls`/`feedback`）；旧 `dsh-advisor` JSONL 不迁移、不读取，`ciel` 设置保留。
- 越界、被保护、截断或无法完整读取的资料不会冒充“不存在”。发生这些情况时，评审显示资料受限/不完整，不能用缺失证据认定作者错误。
- 关闭文件查阅仍可能调用模型分析草稿；旧「把工具次数设为 0」**已不再关闭文件核查**（`criticExploreBudget` / `criticMaxRequests` 整体被忽略，包括 0）。彻底暂停 Ciel 调用应关闭顶层“启用 Ciel”并保存。

## 普通输出和敏感输出

普通终端及 Web 工具输出仍可作为核实阶段的证据，并非一律丢弃。传递前进行敏感内容和已知私有来源检查：

- 凭据形状、已知私有目录、读取 `.env`/私钥/凭据配置、环境变量导出或作者过程来源，触发证据整项扣留；模型不会收到那段原文或文件内容摘要。
- 读取工具仅提供工具名和执行状态摘要，评审应自行查询允许的副本；其他代理及未知过程工具的结果不作为原文证据转发。
- 用户请求、草稿、顾问输入或待发送的证据包中检测到疑似凭据时，直接阻止相关调用并提示先去除敏感内容。
- 隐私扣留会反映为受限覆盖，不偷偷认证完整通过。

**这些内容检查是启发式检测，不是能识别所有秘密的证明。** 将密钥拆分、编码、伪装或直接混进普通源码，仍可能逃过识别；调用者应保持敏感资料与可审阅源码分离。此功能不对抗同机恶意代码、特权挂载攻击或恶意 Host 插件，也不改变 DSH 的全局权限模型。

## 实现边界

`review-corpus.js` 在 Linux 的已验证 procfs 上，以固定目录描述符、`O_NOFOLLOW`、文件身份和读取前后元数据检查捕获文件。随后所有查询只读已拥有的内存字符串；取消和结束会释放副本。允许的源码内容保持原文，不为显示路径别名而改写代码中的字符串；包含受保护绝对路径引用的文件整项扣留。每个文件独立稳定读取，不承诺跨文件的单一瞬间原子快照。默认上限包括 2000 个文件、8 MiB 捕获工作量、单文件 256 KiB，超限会明示受限。不是无限量文件系统镜像。

`review-evidence.js` 把真实 `read`/`grep`/`glob` 结果登记为宿主拥有的 `e1`、`e2`… 引用，并只保存被结果行引用且有界的片段：每条默认 16 KiB / 200 行，每轮评审合计 128 KiB / 128 条。回执由程序接收；进入模型上下文的是程序主动带出的摘要与片段，不是全部回执。完整内存副本在评审结束时释放。`groundReview` 拒绝账本中不存在或未被引用的编号，对应疑点退回未查。`a1` 只是「作者提供输出」的来源标记，原文不另存，覆盖范围因此标为不完整。`contentSha256` 用于一致性检查，不证明防篡改或语义正确。

`record-store.js` 把记录写到 `$DSH_HOME/ciel/v1/<kind>/<sessionId>/<hash(id)>.json`：随机 `wx` 临时文件 + 原子重命名、目录 0700 / 文件 0600、单文件 512 KiB、单会话列表 200 条 / 16 MiB，拒绝符号链接、硬链接和非普通文件，读取前后检查大小与文件身份。没有任意文件 RPC，也不读取旧 `dsh-advisor` JSONL。`readEvidence` 只按已提交评审的 `evidenceIds` 读取，缺失或损坏时明确失败，绝不改读当前文件；当前文件仅由 Host 解析的 `currentPath` 打开。

`review-runner.js` 注册 Ciel 专用的一次性子代理后端：在 Agent 创建事务的 setup 中绑定权限/截止时间守卫、工具呈现方式和专用读接口，**早于第一条模型请求的提示装配**。它不加入父代理的预设工具集合。隔离准备、依赖或守卫失败时直接停止，没有退回普通 `spawn`/文件工具的路径；其他会话的工具不被修改。

0.18.0 起，工具化核实阶段只呈现**原生保留的 `run_code`**：程序在 Ciel 私有的 worker + QuickJS/WASM 中执行（不是 DSH 库存 worker 代码运行时，后者在宿主机上是 bash 等价的），没有环境 Node 全局；只通过声明为 `read`/`grep`/`glob` 的异步绑定访问内存副本，结果是 JSON 字符串。宿主用私有官方 `ToolRuntime` + 私有 `codeRuntime` + 惰性私有 prompt sink，作用域 `tools/execute` 钩子只把该评审子会话的外层 `run_code` 路由到私有官方 PTC 定义；根 `codeRuntime` 不变，语言不匹配或能力缺失时工具化阶段失败，没有不受限回退。私有注册表沿用 DSH 嵌套调度与日志格式，由 Ciel 守卫控制范围与时限；其隔离的嵌套事件不进入根观察者，因此并非所有全局策略插件都作用于该子会话。

文件资料捕获当前要求 Linux、可用 procfs 和所需 Node 文件描述符 API；不支持的平台拒绝文件核查，不使用弱化实现。若调用方挂载了远程文件系统而不能将宿主路径映射为同一个本机路径，也拒绝捕获，不能把远程目录误当成宿主上的同名目录。旧 `dsh-advisor` 记录不再读取；新记录写入 `ciel/v1`。Ciel 声明了共享 DSH 子代理、LLM 与工具模块的可选 peer 依赖（至少对应 **0.1.5-alpha.2** API，其中 `@deepseek-ai/dsh-tools` 用于受限 PTC），并固定 `quickjs-emscripten 0.32.0` 作为插件依赖；首次评审还会验证具体导出能力，缺失时明确报错。没有因此改装用户的运行配置，也不改 DSH 源码或替换全局运行时。

采用设计咨询中的受限资料投影、作用域工具、受限状态外显与设置渐进展开；没有采用单纯路径黑名单、全局工具替换或“换到临时目录就安全”的做法。资料在评审开始时捕获，不冻结在作者动手前，否则无法审查最新成果。

## 时间预算与安全边界

0.17.0 起查询与模型请求次数只统计；默认180秒总时限覆盖资料准备及全部评审阶段，**每个 PTC 程序使用剩余时间，切换阶段不重置**。只限时不等于无限制访问：文件范围、敏感内容、内存副本、PTC 程序的内存/输出上限以及证据/持久化大小上限继续有效，它们是**安全/协议边界，不是查询配额**。超时或取消会硬终止 PTC worker 并排空嵌套调度，不追加抢救模型或延长时间。旧次数设置不再生效，文件核查是否开启仅由 `criticExploreEnabled` 控制。

## 宿主会话日志（重要）

上述片段和大小限制只适用于 Ciel 额外保存的 `ciel/v1` 记录，不是全局无痕承诺。DSH 的标准持久化仍可能把顾问/评审子会话的输入、工具调用与结果（包括未被最终引用的读取）保存到原生 sessions 存储。释放内存副本、关闭侧栏或清理 `dsh-advisor` 旧目录都不会删除这些日志。本版不改宿主留存策略，也不擅自删除用户要求保留的 DSH 会话；敏感内容的输入前拦截仍适用。

## 每次调用的模型

顾问工具和评审卡片显示本次的提供方/模型。`modelUsage.requested` 固定记录当次选择；`used` 从子代理实际助手回复的模型来源提取，并保留多阶段出现的不同路线，不以之后的设置覆盖历史。`/advise` 命令已移除，已有命令模型来源记录仍可读取。

没有回复来源可确认时只显示“请求模型（未确认执行）”，这不代表请求一定没有发送或没有计费。旧记录缺少信息显示“未记录”。顾问工具成功元数据和评审记录直接保存它；命令和工具错误可按精确调用 ID 读取 `$DSH_HOME/ciel/v1/calls/<sessionId>/<hash(id)>.json`（`id` 为 `tool:<callId>` 或 `command:<commandId>`）中仅含身份和路线的记录，不从模型回答文字猜测。
